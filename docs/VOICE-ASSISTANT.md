# Local Voice Assistant

Fully offline voice control for Home Assistant: no cloud STT, LLM, or TTS.

```
Echo Dot satellites (EchoMuse, cluster/apps/iot/echomuse)
   │ audio (ESPHome native API)
   ▼
Home Assistant — Assist pipeline "Local Assistant" (preferred)
   ├─ STT  → whisper.voice.svc.cluster.local:10300   (Wyoming, faster-whisper, GPU)
   ├─ LLM  → ollama.ollama.svc.cluster.local:11434   (native Ollama integration, qwen2.5:7b)
   │         "Prefer handling commands locally" ON → device commands never hit the LLM
   └─ TTS  → piper.voice.svc.cluster.local:10200     (Wyoming, piper, CPU)
```

## Components

All backend pieces live in `cluster/apps/iot/voice/` (namespace `voice`), GitOps-managed:

| Piece | Pod / image | Port | Resources | PVC (no Longhorn backup — regenerable model cache) |
|---|---|---|---|---|
| STT | `whisper`, `lscr.io/linuxserver/faster-whisper:2.0.0-gpu` | 10300 (Wyoming) | GPU `ser-msa2cp1` (`runtimeClassName: nvidia`), model `medium` fp16 ~3 GB VRAM, `WHISPER_LANG=es`, beam 1 | `whisper-config` 10Gi (`longhorn-singlenode`) |
| TTS | `piper`, `lscr.io/linuxserver/piper:1.4.0` | 10200 (Wyoming) | CPU, voice `es_ES-sharvard-medium` | `piper-config` 2Gi (`longhorn-singlenode`) |
| LLM | existing `ollama` (`cluster/apps/ai/ollama`) | 11434 | GPU, `qwen2.5:7b` resident (~4.7 GB VRAM) | — |

VRAM budget on the RTX A2000 (12 GB): qwen2.5:7b ~4.7 GB + whisper medium ~3 GB
≈ 8 GB worst case, leaving headroom for subgen (clears VRAM when idle) and
Jellyfin transcoding. Rule: any new GPU workload must keep the total ≤ ~10 GB.

## Home Assistant configuration (UI, NOT in git)

This config lives on the HA config PVC and is covered by the HA backup. One-time
setup (Settings → Devices & Services → Add Integration, unless noted):

1. **Ollama**: URL `http://ollama.ollama.svc.cluster.local:11434`. Then add a
   conversation agent on the integration entry: name `Ollama Local`, model
   `qwen2.5:7b` (exact tag — must match the model pulled in the ollama pod).
2. **Wyoming Protocol** (twice):
   - host `whisper.voice.svc.cluster.local`, port `10300` → creates `stt.*`
   - host `piper.voice.svc.cluster.local`, port `10200` → creates `tts.*`
3. **Pipeline**: Settings → Voice assistants → Add assistant:
   - Name `Local Assistant`, language Spanish
   - Conversation agent: `Ollama Local`
   - Speech-to-text: faster-whisper (es)
   - Text-to-speech: piper (`es_ES-sharvard-medium`)
   - Enable **Prefer handling commands locally**
   - Mark it as the preferred pipeline (star)
4. **Satellites**: on each EchoMuse/ESPHome satellite device page, select
   `Local Assistant` as its pipeline.

Smoke tests (Assist chat box):
- `¿qué hora es?` → answered by a local intent (no LLM round-trip)
- `encendé la luz de <nombre>` → `action_done` on an exposed light
- `contame un chiste corto` → free-form answer generated by qwen2.5:7b

## Operations

- **Change Whisper model / language**: edit `WHISPER_MODEL` / `WHISPER_LANG` in
  `cluster/apps/iot/voice/whisper-deployment.yaml`, commit, Flux reconciles. The
  new model downloads on first start (pod stays unready meanwhile — expected).
  Mind the VRAM budget above when going larger than `medium`.
- **Change Piper voice**: edit `PIPER_VOICE` in `piper-deployment.yaml`
  (alternatives: `es_ES-davefx-medium`, `es_MX-ald-medium`), commit. The voice
  downloads into the PVC on start.
- **Updates**: Renovate groups both images into one `voice` PR
  (rule in `cluster/infrastructure/renovate/release.yaml`).

## Troubleshooting

- **Satellite stays silent**: check the device has `Local Assistant` selected as
  its pipeline, then `kubectl -n voice get pods` (both must be Ready).
- **Wyoming entry in `setup_retry`**: the backing pod is not Ready yet (first
  start downloads models); check `kubectl -n voice logs deploy/whisper` /
  `deploy/piper`.
- **Slow answers**: `kubectl exec -n ollama deploy/ollama -- nvidia-smi` — if
  VRAM is full (Jellyfin transcoding + whisper + qwen), STT/LLM queue on the GPU.
- **Wrong language detected**: `WHISPER_LANG=es` pins Spanish; if removed,
  short commands get mis-detected.
- **Free-form answers fail but device control works**: ollama issue, not voice —
  `kubectl -n ollama logs deploy/ollama --tail=50`.
